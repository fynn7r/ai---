# 开发上手指南

从零把项目跑起来，预计 10 分钟。**如果你只是想用这个工具，不用看这份文档**，去下载免安装包，双击 `start.bat` 就行。

---

## 一、环境要求

| 项 | 要求 | 为什么 |
|---|---|---|
| Node.js | **≥ 22.18**（23 也行，或 24 LTS） | 服务端用了内置 `node:sqlite`，并且直接 `import` `.ts` 契约文件——依赖 22.18 起默认开启的类型剥离 |
| 系统 | Windows / macOS / Linux 均可 | 免安装打包脚本只管 Windows，开发不分平台 |
| 内存 | 4 GB 以上 | Vite 构建和 Playwright 比较吃内存 |

检查版本：

```bash
node --version     # 需要 v22.18.0 或更高
```

版本不够会直接报 `ERR_UNKNOWN_FILE_EXTENSION`，报错信息看不出根因，先确认版本再排查别的。

> 用 nvm / fnm 的话，项目根目录有 `.nvmrc`，`nvm use` 即可。

## 二、三条命令跑起来

```bash
npm ci        # 装依赖。不要用 npm install，它会改动 lock 文件
npm start     # 一键启动
```

打开终端里打印的地址，默认 <http://127.0.0.1:8001>。

`npm start` 会自动做完四件事：

1. 检查 Node 版本，太低直接拦住并说明原因
2. 从 `.env.example` 复制一份 `.env.local`（已存在则跳过）
3. 检查 `dist-standalone/`，缺产物自动执行一次 `vite build`（约 20-40 秒）
4. 首次运行时创建管理员账号，把初始密码打印在终端 —— **只显示一次**

`.npmrc` 已经指向 npmmirror 国内镜像，不用另外配。

### 开发模式

```bash
npm run dev:standalone
```

前端 8001（热更新），解析服务 3001。改 `src/` 下的代码浏览器自动刷新，改 `server/` 下的 `.mjs` 需要重启（或加 `--watch`）。

## 三、目录怎么走

先记住这一条：**同一份 `src/` 有两个入口，别改错。**

```
standalone.html → src/standalone.tsx → vite.standalone.config.ts → server/index.mjs   ← 独立版，日常开发用这个
index.html      → src/index.tsx      → vite.config.ts            → scripts/build.sh  ← 平台版，上传到秒搭/飞书 aPaaS
```

关键机制在 `vite.standalone.config.ts:33`：把 `@lark-apaas/client-toolkit-lite` 替换成 `src/lib/standalone-runtime.tsx`。一处替换让同一份前端脱离了平台。**改前端时不要直接 import 那个 SDK**，否则独立版会崩。

### 我要改什么，该看哪

| 需求 | 文件 | 体量 |
|---|---|---|
| 改解析效果（提示词、校验、字段） | `server/parse-service.mjs` | 235 行，**最高频** |
| 改日期换算（"下周三"算哪天） | `shared/date-time.ts` | 65 行，前后端都依赖 |
| 改解析页交互 | `src/pages/ParsePage/ParsePage.tsx` | 1387 行，全项目最大 |
| 改规则库 | `src/pages/RulesPage/RulesPage.tsx` | 1006 行 |
| 改待办列表 / 冲突提示 | `src/pages/RemindersPage/RemindersPage.tsx` | 703 行 |
| 加一个新页面 | `src/pages/<Name>/<Name>.tsx` + `src/app.tsx` + `src/lib/nav.ts` | 至少动 3 个 |
| 加一个 API | `server/index.mjs` 挂路由 + 对应的 `*-service.mjs` | |
| 改待办存储 / 版本冲突 | `server/knowledge/reminders-store.mjs` | 323 行 |
| 改知识库检索 | `server/knowledge/search.mjs` | 181 行，FTS5 |
| 改前后端共享的类型 | `shared/*-contract.ts`（Zod） | 7 个文件 |
| 调 UI 组件 | `src/components/ui/*` | shadcn 自动生成，一般别动 |

`shared/capabilities/*.json` 只服务平台版，独立版不读，改前端时不用管。

## 四、改完跑什么

```bash
npm run lint       # typecheck + eslint，pre-commit 钩子会自动跑这个
npm run test:api   # 162 个接口测试，约 13 秒，不花钱、不联网
```

这两条是必须跑的。`npm run test:api` 全部用假模型返回，不会消耗 token。

改到前端流程再用：

```bash
npm run test:browser        # Playwright 端到端，需要先起 dev 服务
```

`npm run verify:live:*` 那几个是**真实调用模型**的验证脚本，会花钱，日常别跑。

提交前不用手动跑 lint —— `.githooks/pre-commit` 会拦。想跳过用 `git commit --no-verify`，但除非在救火，别这么干。

## 五、常见问题

| 报错 | 原因 | 处理 |
|---|---|---|
| `ERR_UNKNOWN_FILE_EXTENSION ".ts"` | Node 版本低于 22.18 | 升级 Node，这是硬要求 |
| `Cannot find module 'node:sqlite'` | Node 版本太低 | 同上 |
| `EADDRINUSE :8001` | 端口被占 | 关掉占用进程，或改 `.env.local` 的 `PORT` |
| `npm ci` 卡在下载 | 镜像没生效 | 确认 `.npmrc` 存在且含 `registry=https://registry.npmmirror.com/` |
| `npm ci` 报 lock 文件不一致 | lock 与 package.json 不同步 | 用 `npm install` 一次重新生成 lock，然后提交 |
| 每次 git 都刷 `LF will be replaced by CRLF` | 缺 `.gitattributes` | 无害，可忽略；要根治就加一行 `* text=auto eol=lf` |
| 前端白屏 | 没构建产物 | `npm run build:standalone` 或直接 `npm start` |
| 解析一直提示未配置 | 没填模型密钥 | 页面「我的 → 模型接入」填，或编辑 `.env.local` |
| 深度解读超时 | 思考型模型输出慢 | 长通知实测约 80 秒，调大 `.env.local` 的 `AI_TIMEOUT_MS` |

## 六、几个约定

- 新增页面放 `src/pages/<PageName>/PageName.tsx`，并在 `src/app.tsx` 的 `<Routes>` 内注册
- `BrowserRouter` 已在入口配好，`app.tsx` 里**不要**再包一层 Router
- 路径别名：`@/` → `src/`，`@shared/` → `shared/`
- 主题色定义在 `src/index.css`，通过 CSS 变量 + `@theme inline` 接入 Tailwind
- 服务端只依赖 3 个第三方包（`@napi-rs/canvas`、`pdfjs-dist`、`zod`），加依赖前先想清楚会不会把免安装包撑大
